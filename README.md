# mcd-points-hunter 麦麦积分猎人

> 把麦当劳积分从「躺着过期」，变成「算着花掉」。

`mcd-points-hunter` 是一个基于**麦当劳中国 MCP** 的 WorkBuddy Skill。
它不帮你点餐，它帮你做一件更值钱的事：**把积分当作资产来管**。

---

## 为什么需要它

麦当劳有三位数以上的会员，几乎每个人都有积分。但积分是一种被系统性忽视的资产：

| 问题 | 后果 |
|---|---|
| 积分有有效期，但没人提前提醒你 | 到期清零，一分钱都换不回来 |
| 商城按积分价排列表，不按性价比排 | 随手挑一个，单位价值可能差 3 倍 |
| 抽奖的期望值从来没人算过 | 花 100 积分抽一次，期望只换回 1.89 元 |
| 抽奖抽到的券容易忘 | 券过期作废，白抽 |

这三个问题都可以用**算术**解决。这就是本项目的全部内容。

---

## 核心能力

### 1. 到期止损：把「还剩 1500 分」翻译成「6 天内每天必须花掉 133 分」

不是告诉你一个静态数字，而是算出**每天的止损速率**，并按风险分级（紧急 / 警告 / 关注 / 安全）。

### 2. 商城划算度排序：算出每积分价值

关键指标：

```
每积分价值 = 权益面值(元) / 消耗积分
```

商城列表按**积分价**排序，恰好把这个差异完全掩盖。本工具按**每积分价值**重排，一眼看出哪个在薅你。

### 3. 抽奖期望值引擎：回答「这批积分该抽还是该换」

```
期望值 EV = Σ(中奖概率 × 奖品价值)
真实 ROI  = 抽奖每积分期望收益 / 积分的机会成本
```

注意这里的**机会成本**：积分本身不是钱，它在商城能换到的权益才是它的价值。
用积分个数当分母是常见错误，会让结论完全反向。

### 4. 蒙特卡洛回测：给出亏损概率，而不只是期望值

固定随机种子（`seed=42`）模拟 20000 次，输出收益分布、亏损概率、中大奖概率。
**结果可复现** —— 同一个输入，任何人在任何机器上跑出的数字都一致。

同时输出**对照情景**：如果你把全部积分冲动投入，会是什么结果。

## 接入麦当劳 MCP（可选，用于真实数据）

本工具的计算部分是纯离线的。要接入真实账户数据，需要配置麦当劳 MCP：

**第一步：申请 MCP Token**

访问 [麦当劳 MCP 开放平台](https://open.mcd.cn/mcp)，手机号登录后在控制台激活并复制 Token。

**第二步：配置连接器**

在 WorkBuddy 左侧边栏【专家·技能·连接器】→【连接器】→【自定义连接器】→【配置MCP】，
填入 `mcp-config.example.json` 的内容，并把 `${MCD_MCP_TOKEN}` 替换成你的真实 Token。

**第三步：导出数据并分析**

让 WorkBuddy 调用对应的 MCP Tool，把返回的 JSON 存成文件，再交给本工具：

```bash
# 积分到期风险
python scripts/points_hunter.py audit --account my-account.json

# 商城划算度排序
python scripts/points_hunter.py mall --products my-products.json

# 抽奖决策（--point-value 为每积分机会成本，通常取商城最优兑换值）
python scripts/points_hunter.py lottery --activity my-lottery.json --point-value 0.0319

# 综合诊断（推荐，自动串联三者并把商城基准传给抽奖模块）
python scripts/points_hunter.py report \
  --account  my-account.json \
  --products my-products.json \
  --activity my-lottery.json
```

所有子命令都支持 `--json` 输出结构化结果，便于二次集成。

> `examples/` 目录下的三个 `.sample.json` 展示了期望的输入结构，
> 分别对应 `query-my-account`、`mall-points-products`、`query-lottery-info` 的返回。

## 目标用户

- **麦当劳高频会员**：积分多、变化快，需要持续管理而不是偶尔看一眼
- **积分即将到期的用户**：最刚需，本工具能直接挽回实际损失
- **习惯薅羊毛的消费者**：关心「怎么换最划算」而不是「有什么可以换」
- **对抽奖心动但不确定的人**：需要一个数字来阻止冲动消费
- **开发者**：可把 `scripts/engine/` 当作纯计算库，接入自己的应用

## 设计说明

**为什么引擎不直接调用 MCP？**
数据获取交给 WorkBuddy 智能体层，计算逻辑保持纯函数、零网络请求。
好处是全部逻辑可离线自测、可复现、可移植到任何语言或应用。

**为什么要兼容字段别名？**
MCP 的返回字段在不同 Tool、不同版本间存在命名差异（`points` / `pointsCost` / `integral`）。
`engine/common.py` 统一做了一层候选字段映射，避免业务代码到处写 `or` 兜底。

**为什么坚持用分位数而不是硬编码阈值？**
不同时期、不同账户的商品池差异很大。绝对阈值会随时间失效，
按分位数给出「相对评级」才能长期稳定。

**为什么拿不到概率时不编数据？**
概率字段缺失时降级为等概率假设，并在输出里明确标注 `confidence: low`。
拿不到的价值一律按 0 计 —— 宁可低估，绝不臆造。
